# WeaveSocks Synthetic Monitoring

## 1. Описание проекта

В рамках работы реализован синтетический мониторинг веб-портала WeaveSocks. Проверка выполняется не через прямые HTTP-запросы к отдельным API, а через эмуляцию действий обычного пользователя в браузере.

Сценарий выполняется средствами Selenium и Python. Результаты каждого шага передаются в Pushgateway, откуда их забирает Prometheus. Grafana используется для отображения длительности транзакции, длительности отдельных шагов и результатов выполнения.

Контрольный адрес приложения:

`http://89.232.176.168/`

Тестовая учетная запись:

`user2 / user2`

Основная идея решения — получать не только информацию о доступности HTTP-сервиса, но и проверять, что пользователь действительно может выполнить целевой бизнес-сценарий от открытия сайта до работы с корзиной.

---

## 2. Цель работы

Необходимо было разработать периодическую проверку веб-ресурса с эмуляцией действий пользователя и передавать в систему мониторинга информацию о:

- успешности выполнения сценария;
- длительности каждого основного шага;
- общей длительности транзакции;
- состоянии результата в исторической динамике.

Проверяемый сценарий соответствует заданию:

1. открыть главную страницу и проверить заголовок `WeaveSocks`;
2. выполнить авторизацию `user2/user2` и проверить `Logged in as Test User`;
3. перейти в `Catalogue` и найти товар `Colourful`;
4. добавить `Colourful` в корзину и проверить `1 item(s) in cart`;
5. открыть корзину и проверить товар `Colourful`, количество `1` и стоимость `$18.00`;
6. удалить товар, выполнить `Update basket`, убедиться в состоянии `0 items in cart` и выйти из аккаунта.

Шаги 1–5 используются для расчета основной транзакции. Очистка корзины и выход из аккаунта относятся к завершающей части сценария и в расчет `N0` не включаются.

## 4. Компоненты решения

### Selenium

Используется для управления браузером и выполнения последовательности пользовательских действий: открытие страниц, нажатие ссылок и кнопок, ввод логина и пароля, работа с корзиной.

Selenium работает с Chromium в headless-режиме, поэтому отдельное графическое окно браузера для работы мониторинга не требуется.

### Chromium

Браузер, которым управляет Selenium внутри контейнера. Используется реальный браузерный движок, поэтому проверяются не только HTTP-ответы, но и фактическое состояние пользовательского интерфейса.

### Python

`monitor.py` содержит сценарий проверки, логику ожидания элементов, обработку ошибок и формирование Prometheus-метрик.

После выполнения одного запуска браузер закрывается. Следующий запуск начинается с нового экземпляра Chromium.

![Selenium и Python](https://github.com/lamjob1993/selenium-monitor/blob/main/screenshots/selenium%2Bpython.png)

### Pushgateway

Получает метрики от Python-процесса через `push_to_gateway()`.

Использование Pushgateway связано с тем, что проверка является периодическим batch-сценарием: Python запускает тест, получает результат и передает его в Pushgateway.

![Pushgateway](https://github.com/lamjob1993/selenium-monitor/blob/main/screenshots/pushgateway.png)
![Pushgateway](https://github.com/lamjob1993/selenium-monitor/blob/main/screenshots/pushgateway_2.png)

### Prometheus

Собирает метрики из Pushgateway и хранит временной ряд для дальнейшего анализа.

![Prometheus](https://github.com/lamjob1993/selenium-monitor/blob/main/screenshots/prometheus.png)
![Prometheus](https://github.com/lamjob1993/selenium-monitor/blob/main/screenshots/prometheus_2.png)

### Grafana

Используется для визуализации результатов. Основной график показывает общую длительность транзакции и длительность отдельных шагов в одной временной шкале.

### Docker Compose

Объединяет компоненты в единый проект и обеспечивает запуск сервисов одной командой.

## 6. Сценарий тестирования

### N01 — Главная страница

Selenium открывает:

`http://89.232.176.168/`

Проверка успешности выполняется по заголовку страницы. Ожидаемое значение содержит:

`WeaveSocks`

Для загрузки страницы используется `page_load_strategy = eager`, поэтому Selenium не ждет завершения загрузки всех второстепенных ресурсов, если основной DOM уже доступен.

### N02 — Авторизация

Открывается форма входа, вводятся:

- username: `user2`
- password: `user2`

После отправки формы выполняется проверка текста:

`Logged in as Test User`

### Предварительное состояние корзины

Учетная запись `user2` используется совместно, поэтому корзина сохраняется между запусками и может содержать товары от предыдущих проверок.

Перед измеряемыми шагами N03–N05 выполняется подготовка окружения. Если корзина не пустая, позиции удаляются через `deleteFormCart(...)`, затем вызывается `updateCart()`. Проверкой окончания подготовки служит состояние:

`0 items in cart`

Этот этап не входит в `N0`.

### N03 — Catalogue

В меню выбирается `Catalogue`.

Товар `Colourful` ищется только внутри контейнера каталога `#products`. Это исключает совпадения с дополнительными рекомендационными блоками, в которых также может присутствовать товар `Colourful` с ценой `$18`.

### N04 — Add to cart

В карточке товара `Colourful` нажимается `Add to cart`.

После действия проверяется фактическое количество товаров в корзине. Ожидаемое значение:

`1 item(s) in cart`

### N05 — Cart

Открывается ссылка корзины `basket.html`.

Проверяется именно строка товара внутри `#cart-list`, а не текст всей страницы. Для успешного результата требуется:

- ровно одна строка `Colourful`;
- quantity = `1`;
- unit price = `$18.00`;
- total = `$18.00`.

Блок с `Colourful` вне таблицы корзины при этом не учитывается.

### Cleanup

После окончания измеряемой транзакции выполняется завершающая часть сценария:

1. нажимается иконка удаления через `deleteFormCart(...)`;
2. нажимается `Update basket` через `updateCart()`;
3. проверяется `0 items in cart`;
4. выполняется `Logout`.

Cleanup не входит в `N0`.

## 7. Метрики

В проекте используются четыре семейства Prometheus-метрик.

### Общая длительность транзакции

```text
synthetic_transaction_duration_seconds
```

Значение `N0` рассчитывается в Python как сумма длительностей пяти основных шагов:

```text
N0 = N01 + N02 + N03 + N04 + N05
```

### Результат транзакции

```text
synthetic_transaction_success
```

Значения:

- `1` — транзакция завершена успешно;
- `0` — транзакция завершена с ошибкой.

### Длительность отдельного шага

```text
synthetic_step_duration_seconds{step="..."}
```

Используемые значения `step`:

```text
home
auth
catalogue
add_to_cart
cart
remove_from_cart
update_basket
logout
```

### Результат отдельного шага

```text
synthetic_step_success{step="..."}
```

`1` означает успешное выполнение шага, `0` — ошибку.

## 8. Связь метрик с заданием

| Обозначение | Действие | Prometheus series |
|---|---|---|
| N01 | Главная страница | `synthetic_step_duration_seconds{step="home"}` |
| N02 | Авторизация | `synthetic_step_duration_seconds{step="auth"}` |
| N03 | Каталог товаров | `synthetic_step_duration_seconds{step="catalogue"}` |
| N04 | Добавление в корзину | `synthetic_step_duration_seconds{step="add_to_cart"}` |
| N05 | Открытие корзины | `synthetic_step_duration_seconds{step="cart"}` |
| N0 | Общая транзакция | `synthetic_transaction_duration_seconds` |

Статус выполнения соответствующих операций дополнительно контролируется через `synthetic_step_success` и `synthetic_transaction_success`.

## 9. Grafana

Основная панель отображает шесть серий:

```text
[N0]  Общая транзакция
[N01] Главная страница
[N02] Авторизация
[N03] Каталог товаров
[N04] Добавление в корзину
[N05] Открытие корзины
```

По оси X используется временная шкала, по оси Y — длительность выполнения.

Для отображения последних измеренных значений используется `Last not null`.

В основной график не включены:

- `remove_from_cart`;
- `update_basket`;
- `logout`.

Они относятся к завершающей части сценария и не входят в `N0`.

## 10. Периодичность проверки

По условиям задания полный сценарий должен выполняться один раз в 5 минут.

В `monitor.py` это задается параметром:

```python
CHECK_INTERVAL = 300
```

Во время разработки и отладки использовался укороченный интервал в несколько секунд, чтобы быстро проверять изменения сценария. Перед финальной демонстрацией интервал выставляется в 300 секунд.

Таймаут ожидания отдельного Selenium-условия задается отдельно:

```python
SELENIUM_TIMEOUT = 5
```

Эти параметры имеют разное назначение: первый отвечает за периодичность теста, второй — за максимальное время ожидания конкретного состояния страницы.

---

## 11. Обработка ошибок

Для каждого шага отдельно фиксируются результат и длительность.

Если ожидаемый элемент или текст не появляется в течение установленного таймаута, шаг получает статус `FAILED`, а длительность фиксируется до момента возникновения ошибки.

Если, например, каталог недоступен, карточки товаров не загружены или веб-сервис отвечает `no available server`, это должно отражаться как реальный отказ пользовательского сценария, а не скрываться дополнительными бесконечными повторами.

При частично выполненном сценарии последующие шаги не запускаются, если их выполнение зависит от предыдущего результата.

## 12. Особенности тестового стенда

Во время проверки были обнаружены особенности самого тестового приложения.

### Общая корзина пользователя

Корзина пользователя `user2` сохраняется между запусками. При повторных добавлениях количество товаров может накапливаться, поэтому перед каждым измеряемым сценарием выполняется подготовка корзины до состояния `0 items in cart`.

### Нестабильность приложения

В ходе тестирования наблюдались ситуации, когда:

- главная страница открывалась с задержкой;
- каталог загружался неполностью;
- карточки товаров временно отсутствовали;
- приложение возвращало `no available server`;
- отдельные операции превышали допустимое время ожидания.

Такие события рассматриваются как реальные результаты synthetic monitoring. Задача мониторинга состоит не в том, чтобы скрыть подобные ошибки, а в том, чтобы зафиксировать их и показать в Grafana.

## 13. Запуск проекта

Из каталога проекта:

```bash
docker compose up -d
```

Проверка состояния контейнеров:

```bash
docker compose ps
```

Просмотр логов Selenium:

```bash
docker compose logs -f selenium-monitor
```

Пересборка только Selenium после изменения `monitor.py`:

```bash
docker compose build --no-cache selenium-monitor
docker compose up -d --force-recreate selenium-monitor
```

Полная пересборка и запуск проекта:

```bash
docker compose down
docker compose up -d --build
```

## 14. Ожидаемый результат работы

При успешном запуске в логах должен присутствовать примерно следующий порядок событий:

```text
[SUCCESS] home
[SUCCESS] auth
Precondition complete: 0 items in cart
[SUCCESS] catalogue
[SUCCESS] add_to_cart
[SUCCESS] cart

TRANSACTION RESULT: SUCCESS
N0 TRANSACTION DURATION: ... sec

[SUCCESS] remove_from_cart
[SUCCESS] update_basket
Basket successfully emptied: 0 items in cart
[SUCCESS] logout

Metrics successfully pushed to Pushgateway
Waiting 300 seconds before next check...
```

При проблемах с веб-приложением соответствующий шаг получает `FAILED`, а в Grafana появляется увеличение длительности либо отсутствие успешного выполнения шага.

## 15. Результат выполнения работы

В результате реализован полный синтетический сценарий для WeaveSocks с использованием Selenium и Python.

Сценарий проверяет не только доступность главной страницы, но и последовательность пользовательских действий: авторизацию, работу каталога, добавление товара в корзину, открытие корзины и проверку цены.

Полученные значения передаются в Prometheus через Pushgateway и отображаются в Grafana. Это позволяет одновременно видеть текущий результат и историю изменения времени выполнения пользовательского сценария.

Отдельно учитывается состояние общей корзины тестового пользователя, что позволяет запускать сценарий повторно без накопления предыдущих позиций.

---

## 16. Вывод

Решение закрывает основные пункты задания: автоматизированный пользовательский сценарий реализован на Selenium + Python, длительность и результат шагов собираются в Prometheus, данные передаются через Pushgateway, а Grafana используется для визуализации.

Система также позволяет увидеть реальные проблемы тестового стенда: недоступность сервиса, задержки загрузки, отсутствие товаров в каталоге и ошибки на отдельных шагах пользовательского сценария.
